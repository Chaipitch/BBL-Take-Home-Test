## 1. Conventions

- **Base URL (dev):** `http://localhost:4000`. CORS allows only `http://localhost:3000` [003]; other origins get no `Access-Control-Allow-Origin` header.
- **Auth:** every route requires `Authorization: Bearer <Auth0 access token>` for audience `https://bbl-candidate-test-api` [008, 010]. There are no public routes.
- **Content type:** request and response bodies are JSON. A body that isn't valid JSON fails validation → `400` [012m].
- **IDs:** UUID v4 strings, generated by the server [004].
- **Timestamps:** ISO 8601 UTC strings, e.g. `"2026-09-17T10:47:39.124Z"`.
- **Nulls:** optional fields are always present, as `null` when empty — never omitted [012g].
- **Identity:** the owner is always the authenticated user. `ownerId` is never accepted from the client [012d].

## 2. Errors [012a, 012b]

All errors use **RFC 9457 Problem Details**, `Content-Type: application/problem+json`:

```json
{
  "type": "about:blank",
  "title": "Not Found",
  "status": 404,
  "detail": "The requested resource was not found",
  "code": "not_found"
}
```

Validation errors add a field list:

```json
{
  "type": "about:blank",
  "title": "Bad Request",
  "status": 400,
  "detail": "Request validation failed",
  "code": "validation_failed",
  "errors": [{ "field": "url", "message": "must be an absolute http or https URL" }]
}
```

| Status | `code` | When |
|---|---|---|
| 400 | `validation_failed` | Body or query fails validation; unknown or server-owned fields; malformed JSON; bad cursor; empty PATCH; `collectionId` on a bookmark that isn't the caller's collection [012d, 012f, 012h, 012k] |
| 401 | `unauthorized` | Missing/invalid token. **Identical body for every cause**; `WWW-Authenticate: Bearer` (+ `error="invalid_token"` when a token was sent) [010e] |
| 404 | `not_found` | Resource doesn't exist, **belongs to someone else**, or the path id isn't a UUID — **identical response in all three cases** [004a] |
| 409 | `collection_not_empty` | `DELETE /collections/:id` on a non-empty collection without `?confirm=true`; body adds `"bookmarkCount": <n>` [005b] |
| 413 | `payload_too_large` | Request body larger than 100 KB [013e] |
| 500 | `internal_error` | Unexpected failure; no internal details in the body |
| 503 | `service_unavailable` | Token signing keys unavailable [010e] |

## 3. Resources [012g — brief §3.1.4 shape]

### Collection
```json
{ "id": "uuid", "name": "string", "ownerId": "uuid", "createdAt": "timestamp", "updatedAt": "timestamp" }
```

### Bookmark
```json
{
  "id": "uuid", "url": "string", "title": "string", "notes": "string | null",
  "collectionId": "uuid | null", "ownerId": "uuid", "createdAt": "timestamp", "updatedAt": "timestamp"
}
```

### Relation and on-delete
- A bookmark belongs to **zero or one** collection (`collectionId` nullable = uncategorised) and to exactly one owner.
- A bookmark can only reference a collection **with the same owner** — checked in the service **and** enforced by a composite foreign key `Bookmark(collectionId, ownerId) → Collection(id, ownerId)` [005a].
- **Deleting a collection deletes its bookmarks** (and its shares) — `ON DELETE CASCADE` [005]. Non-empty collections require `?confirm=true` [005b].
- Duplicate collection names are allowed [007].

## 4. Input rules [012c, 012d, 012e]

Validated with zod schemas through Nest's `StandardSchemaValidationPipe`. Objects are **strict**: any key not listed below → `400`.

| Field | Rule |
|---|---|
| `name` (collection) | string, trimmed, 1–200 chars |
| `url` | string, trimmed, absolute URL with scheme `http` or `https` only, ≤ 2048 chars. Stored as given (no normalisation, never fetched). |
| `title` | string, trimmed, 1–500 chars |
| `notes` | string or `null`, trimmed, ≤ 10 000 chars; empty after trimming → stored as `null` |
| `collectionId` (body) | UUID or `null`; must be one of the caller's collections, else `400` (`field: collectionId`) [012k] |
| `id`, `ownerId`, `createdAt`, `updatedAt` | **rejected** in any request body → `400` |

### PUT vs PATCH [012f]
- **PUT** replaces all client-editable fields. Required: collection `name`; bookmark `url`, `title`. Bookmark `notes` and `collectionId` are optional and **become `null` when omitted**. PUT never creates: unknown id → `404`.
- **PATCH** changes only the fields sent. `null` clears `notes` / `collectionId`; `null` on a required field → `400`. An empty body `{}` → `400`.
- Both return `200` with the updated resource.

## 5. Lists, pagination, filters [012h, 012i]

List responses:
```json
{ "data": [ ... ], "nextCursor": "opaque-string-or-null" }
```

| Query param | Applies to | Rule |
|---|---|---|
| `limit` | all lists | integer 1–100, default 50 |
| `cursor` | all lists | opaque value from a previous `nextCursor`; malformed or tampered → `400` |
| `name` | `GET /collections` | case-insensitive *contains* on name; 1–200 chars |
| `collectionId` | `GET /bookmarks` | a UUID → bookmarks in that collection; `none` → uncategorised only. Malformed → `400`. A UUID that isn't the caller's collection → `200` with an empty list (same as an empty collection of theirs) |
| `q` | `GET /bookmarks`, `GET /collections/:id/bookmarks` | case-insensitive *contains* on **title** only; 1–500 chars |

- **Order:** newest first — `createdAt desc, id desc` (fixed; no `sort` parameter).
- **Cursor pagination (keyset):** the cursor encodes the last item's `(createdAt, id)`; the next page is items strictly after it in the order above. Pages don't shift when items are added or removed between requests.
- **Unknown query parameters → `400`.**
- Every list query is scoped by the caller's `ownerId` before any filter is applied.

## 6. Endpoints

### `GET /me` — implemented
`200` → `{ "id": "uuid", "email": "string | null", "emailVerified": boolean, "name": "string | null" }` [011g].
The user row is created and its profile synced from Auth0 `/userinfo` inside the auth guard (first request, then when older than 24 h) [009, 011].

### Collections — implemented (BBL-13)

| Method & path | Body | Success | Errors |
|---|---|---|---|
| `GET /collections` | — | `200` list of Collection | 400 (query) |
| `POST /collections` | `{ name }` | `201` Collection + `Location: /collections/{id}` | 400 |
| `GET /collections/:id` | — | `200` Collection | 404 |
| `PUT /collections/:id` | `{ name }` | `200` Collection | 400, 404 |
| `PATCH /collections/:id` | `{ name? }` (≥ 1 field) | `200` Collection | 400, 404 |
| `DELETE /collections/:id` | — ; query `confirm=true` | `204` | 404; `409 collection_not_empty` + `bookmarkCount` if it has bookmarks and `confirm` is absent; `400` if `confirm` has any value other than `true` |
| `GET /collections/:id/bookmarks` | — ; query `limit`, `cursor`, `q` | `200` list of Bookmark | 400 (query), 404 (collection) [012j] |

Known and accepted races [012l, 013d]: delete runs as *find → count → delete*. A bookmark added between a `409` and the confirmed retry is deleted too; and a bookmark added in the milliseconds between the count (0) and the delete is deleted even though `confirm` was not sent.

### Bookmarks — implemented (BBL-14)

| Method & path | Body | Success | Errors |
|---|---|---|---|
| `GET /bookmarks` | — ; query `limit`, `cursor`, `collectionId`, `q` | `200` list of Bookmark | 400 (query) |
| `POST /bookmarks` | `{ url, title, notes?, collectionId? }` | `201` Bookmark + `Location: /bookmarks/{id}` | 400 |
| `GET /bookmarks/:id` | — | `200` Bookmark | 404 |
| `PUT /bookmarks/:id` | `{ url, title, notes?, collectionId? }` | `200` Bookmark | 400, 404 |
| `PATCH /bookmarks/:id` | any of `url`, `title`, `notes`, `collectionId` (≥ 1) | `200` Bookmark | 400, 404 |
| `DELETE /bookmarks/:id` | — | `204` | 404 |

## 7. How the privacy invariant is enforced

> Every row belongs to one owner; a user must never see, modify, or learn of the existence of another user's data (brief §3). Only exception: collections explicitly shared read-only, served under `/shared/...` (ADR-006, BBL-15).

| Layer | Mechanism | Status | Proof |
|---|---|---|---|
| Authentication | Global `AuthGuard`, deny by default; RS256 only, exact issuer, audience contains the API, `exp`/`sub` required | Implemented | `backend/src/auth/auth.guard.spec.ts` (+ mutation checks, real-token check) |
| Identity source | `ownerId` comes only from `@CurrentUser().id`, resolved from the verified token's `sub`; never from body/query/params; request bodies containing `ownerId` → `400` | Implemented | `test/users.e2e-spec.ts`; `test/collections.e2e-spec.ts` (ownerId in POST/PUT/PATCH) |
| Data access | Every query on owned data filters by `ownerId`; single-row reads/writes use `id_ownerId` (collections) or `{ id, ownerId }` (bookmarks), so not-found and not-yours are the same Prisma result | Implemented | `test/collections.e2e-spec.ts`, `test/bookmarks.e2e-spec.ts` cross-user tests for every route; mutation checks: removing `ownerId` from any get/update/delete/list fails tests |
| Existence hiding | "not yours", "doesn't exist" and malformed path id → identical `404` (fixed `detail` text); `?collectionId=` of someone else's collection → same empty page as an own empty collection or a random id; assigning someone else's collection → same `400` as a random id; UUIDs | Implemented | both e2e files compare the response bodies for equality |
| Relation integrity | Service check (`id_ownerId` lookup → 400) **and** composite FK `(collectionId, ownerId)`; an FK race maps to the same 400 | Implemented | `test/bookmarks.e2e-spec.ts` (POST/PUT/PATCH into B's collection); `bookmarks.service.spec.ts` (FK race mapping); mutation: removing either layer alone keeps the API correct, removing both fails 3 tests |
| Stored-XSS prevention | Bookmark URLs must be absolute `http`/`https`; plain `z.url()` would accept `javascript:`/`data:`/`file:` | Implemented | `test/bookmarks.e2e-spec.ts` URL cases; mutation: plain `z.url()` fails 6 tests |
| Input validation | Every body/query goes through a zod schema via `@ValidBody`/`@ValidQuery`; strict objects; a test inspects every registered route and fails on a bare `@Body`/`@Query` (Nest's pipe silently skips params without a schema) | Implemented | `test/api-guardrails.e2e-spec.ts` (self-tested; mutation: bare `@Body()` fails it) |
| Profile/email | Email for sharing comes only from Auth0 `/userinfo` server-side, verified flag required | Implemented | `test/users.e2e-spec.ts` |

## 8. Where the agent's first attempt was wrong

1. **Auth errors: outage reported as "invalid token".** A first design mapped jose errors to 401; jose throws a *generic* `JOSEError` when the JWKS endpoint returns non-200, so an Auth0 outage would have logged users out. Found by reading jose's source; fixed by classifying explicit error codes (401 vs 503). [ADR-010 notes]
2. **Test helper made negative tests use valid tokens.** `SignJWT` setters overwrote the "bad" claims; 4 rejection tests failed and one acceptance test passed for the wrong reason. Found on first run; payload now built as one object. Mutation testing then showed the RS256 pin was untested → added a PS256 case. [ADR-010 notes]
3. **Prisma upsert assumed atomic.** With `update: {}` Prisma runs SELECT-then-INSERT; 9/10 parallel first sign-ins returned 500. Caught by a parallel e2e test, measured 171/200 failures, fixed with a non-empty update. [ADR-011 notes]
4. **Contract draft deviated from the brief** — recommended omitting `ownerId` from responses; developer rejected it; now follows the brief's resource shape. [ADR-012g]

5. **Filters treated `%` and `_` as wildcards.** Assumed Prisma escapes `contains` values; a test written to check that assumption showed `?name=%` matched every collection. Fixed with `common/filters.ts` (escapes `\`, `%`, `_`). [ADR-013 notes]
6. **Unvalidated input would compile silently.** Nest 12's schema pipe skips any `@Body()`/`@Query()` without a schema — found by reading the pipe's source before building; guarded by `@ValidBody`/`@ValidQuery` plus a route-metadata test. [ADR-013f]
7. **Flaky e2e tests blamed on the wrong cause first.** ~20% of runs failed with random 401/404/HTTP parse errors. Keep-alive was suspected and disproved (`Connection: close` didn't help). Actual cause: supertest listening per request on `::` while other local apps held the same port on 127.0.0.1. Fixed by listening once on 127.0.0.1 (0/20 failures after). [ADR-013 notes]

8. **URL validation that looks right but allows XSS.** The natural implementation, `z.url()`, accepts `javascript:alert(1)`, `data:` and `file:` URLs. Found by probing zod before building; the contract's http/https rule is enforced with `z.url({ protocol: /^https?$/ })` and 6 tests fail if the restriction is removed. [ADR-014d]
